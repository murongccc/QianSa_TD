# 三指抓包分析与实现范围

本轮只分析用户提供的四份原始 HEX 抓包，没有修改主工程 RTL，也没有运行综合或布局布线。

## 实测结果

| 抓包 | 完整有效帧 | 最大同时按住数 | 校验错误 | 文件内部序列缺口 |
|---|---:|---:|---:|---:|
| touch_01_three_down_release | 523 | 3 | 0 | 0 |
| touch_02_third_move | 699 | 3 | 0 | 0 |
| touch_03_contact_replace | 668 | 3 | 0 | 0 |
| touch_04_four_limit | 533 | 4 | 0 | 0 |

共 2423 帧，全部为 `57 AB 88 39`，IDENT=40、报告ID=0D；没有截断帧、跳过字节、保留位错误、重复编号或记录数量与内容不一致。文件间没有检查序列连续性。

报告保持原长度57，最多10条5字节记录；本次实测使用前1..4条，余下记录为零。第三条记录处于 body[12..16]，第四条处于 body[17..21]；body[54]为记录数（包含松开），body[55]为序号。body[52..53]始终为01 01，但本次未进一步解释这两个字段。

第一组第176帧出现编号3/2/1同时按住，对应坐标(14320,4832)/(7664,5264)/(848,5056)。第341帧编号3的down变0，数量仍为3；第342帧才变成两条记录。

第二组的三指保持段有443帧：编号3有179种位置，Y范围2752..6992；编号1、2各只有一个坐标。证明第三指独立移动，不覆盖前两指。

第三组编号3先松开，再以同一编号、不同坐标重新按下；期间编号1、2持续保持。编号复用必须依据松开/重新按下识别，不能永久记忆某编号的轨道。

第四组有57帧四指同时按住，编号4/3/2/1均独立。第283帧编号4松开，报告仍有四条记录且前三指继续按住；下一帧才缩为三条。

## 对设计的要求

- 用户选择只增加三指游戏判定，保留A/B十字及现有T/S行格式，不增加第三指坐标显示。
- 用户选择四指时保留已有三指，忽略额外触点；被忽略触点必须实际松开再按下才能参与。
- 不能只读取报告前三条：新指优先排列，第四指按下后顺序为4/3/2/1，原编号1在第四条。
- 必须接收并校验包含第四条的完整报告，再按身份保留原三指。不能拒绝整帧并冻结旧状态，否则会漏掉三指中的释放。
- 松开记录计入数量，不能把数量直接当作当前按住数。接触消失处理仍需遵循完整有效快照；错误报告不制造松开。
- 记录被忽略的编号及接触生命周期，不能在已有三指之一松开时直接提升仍按住的第四指。
- 资源方案优先串行匹配/边界比较，仅维护三个可参与触点和少量身份状态，不复制第四指坐标流水线或视频标记。
- 现有四位轨道掩码、CDC队列及Tap/Hold核心接口保持原值；三指绑定结果在整份报告处理完成后统一合并发布。

## 未实测情况

未抓到同一帧中旧指松开与新编号按下的组合；编号3在第三组被复用，因此不能据此声称测过新编号替换。没有时间戳，不能从这些文本求实际报告周期或触摸延迟。五至十指行为、非逆序松开以及异常帧后的行为仍需仿真覆盖，必要时补充实测。

本批抓包用于协议验证，主要按下坐标不在底部游戏操作区内，不作为三轨游戏命中的验收证据。
