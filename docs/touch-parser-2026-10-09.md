## 上板和 XCOM 设置

1. 在 TD 打开主工程 `E:/AnLuTD_Project/SD_to_Video/prj/SD_to_Video.al`，从综合开始构建，由用户生成 bitstream 并下载。本阶段使用主工程，不再下载原来的 `touch_uart_debug.al` 透传工程。
2. 接线保持：CH9350 TX → J2 第 1 脚；RX → J2 第 2 脚；GND → J2 第 12 脚。模块 5 V 供电、屏幕 POWER 供电和当前正常工作的 TOUCH 数据线保持。
3. CH9350 五个拨码仍按模块 PCB 的 0/1 标识全部置 1：SEL=1、S0/S1=1、BA0/BA1=1，115200。
4. XCOM 打开板载 CH340 的 COM 口，设置 115200、8 数据位、1 停止位、None 校验，DTR/RTS 不勾选。
5. **取消勾选“16进制显示”**，现在接收的是可读 ASCII 文本。发送快捷键时也取消“16进制发送”和“发送新行”。
6. 给 CH9350 重新上电后，FPGA 会自动应答 `57 AB 82 A?` 请求，不需要在电脑发送 11 字节应答。电脑串口现在用于监视及原快捷键，发送内容不会转发到 CH9350。
7. 触摸、滑动、分别松开两个手指，保存接收窗口。KEY1 复位会清空状态和统计；收到新的模块状态请求也会清除旧按住状态，避免跨模块重启保留触点。

没有触摸时，每秒应看到一条 `S` 统计行，可以先用它判断 FPGA 串口输出是否运行。模块先前已经接受过应答且未重新上电时，`ack=0000` 也可能是正常的，应结合 `ok` 判断。

## 文本格式

```text
T 41 A:1,1,0C10,1980 B:2,1,0BD0,0FC0 P:2 R:0
S ok=0002 sum=0000 fmt=0000 gap=0000 rx=0000 to=0000 ack=0001 drop=0000 echo=0000
```

所有数值均为十六进制。

- `T` 后的 `41` 是该次报告的 8 位序列号。
- `A`、`B` 是 FPGA 维护的两个跟踪槽，每槽依次为 **触点编号、按住状态、X 原始坐标、Y 原始坐标**。
- A/B 按编号保持对应关系，不等同于报告中的第一/第二条记录，也不保证 A 总是手指 1。重新分配后编号可以变化。
- 按住状态 1 表示按住，0 表示松开。松开后保留最后坐标用于观察；坐标非零不能用于判断按住。
- `P` 为本帧按下事件，`R` 为松开事件。值 1 对应 A，2 对应 B，3 对应两个槽。若同一槽在一帧中由旧编号换为新编号，P/R 的对应位可同时为 1；释放针对旧编号，按下针对新编号。
- 普通坐标更新最多约 20 Hz 取样输出，按下/松开和模块重启清状态优先入队。`T` 行序列号跳跃是输出限频的正常现象；真实接收流是否跳号看 `S gap`。

| 统计字段 | 含义 |
|---|---|
| ok | 完整、校验正确且符合目标触摸格式的报告数量 |
| sum | CH9350 8 位累加和校验失败数量；不是 CRC16 |
| fmt | 异常长度、错误状态请求参数、非目标 HID 格式或不支持的触点记录数量 |
| gap | 校验正确的 88 帧序列不连续次数；正常 FF→00 回绕不计，跳号后仍接受合法快照 |
| rx | UART 停止位错误数量 |
| to | 收到半帧后连续 20 ms 无新字节，丢弃半帧的次数 |
| ack | 自动送出的状态 0 应答包数量 |
| drop | 四项触摸监视队列溢出数量，仅表示监视文本未能保留全部候选快照 |
| echo | 十六字节快捷键回显队列溢出数量；命令本身仍由原控制器处理 |

统计为 16 位，按 65536 回绕。回显字符只在完整文本行之间输出，不插入触摸或统计行。频繁发送命令或快速制造大量状态变化仍可能使监视队列溢出；计数会显式反映，解析器不等待文本发送器。

## 解析规则和接口

外层帧为 `57 AB 88 LEN IDENT PAYLOAD SEQ SUM`。LEN 必须在 3—72 内；累加校验只覆盖 PAYLOAD 和 SEQ。按 LEN 收帧，不把载荷中的 `57 AB` 当成新帧头。UART 错误或半帧超时会放弃当前半帧，并重新搜索后续合法帧。

目标触摸报告要求 LEN=57、IDENT=40/41（两种 USB 端口标识）、PAYLOAD 首字节=0D，54 字节载荷。仅使用已经实测验证的最多两条 5 字节记录：状态/编号、X低、X高、Y低、Y高。

当前屏幕的状态字节高 4 位作为编号，bit 0 作为按住标志，bit 3:1 必须为 0。尾部第 54 字节作为报告记录数，可以是 0、1、2，包含松开记录；它不等于当前按住数量。未使用的记录区要求为零；超过两个记录、重复编号和非目标报告均拒绝并计入 fmt。尾部固定的 01 01 不参与判断，其完整含义仍需 HID 描述符确认。

只有校验和格式同时通过，才在 50 MHz 域原子发布两点快照及一拍 `update_valid`、`press_mask`、`release_mask`。错误报告保持上一份有效快照，不制造按下事件。完整快照中缺失的旧编号按松开处理。收到有效状态请求则清旧按住状态并请求自动应答，序列号跟踪开始新周期。

`ch9350_touch_input` 输出：`a_id/a_down/a_x/a_y`、`b_id/b_down/b_x/b_y`、`frame_seq`、`update_valid`、两位事件掩码及统计。当前只连接串口监视器。将来接 25 MHz 视频/游戏域时，需要完整事件和快照的跨时钟域传递，不能直接分别同步坐标总线。

无数据期间不会仅凭时间判断长按已经松开：没有实现全链路失联看门狗。物理断线且最后一次松开报告丢失时，状态可能保持到下次合法快照、模块状态请求或 KEY1 复位。游戏接入阶段需在确认报告持续上报行为后制定失联清状态策略。
