# 用 HX4S20 板载 CH340 检查 CH9350 串口数据

开发板已经带有 CH340 USB 转串口芯片，可以把 CH9350 的串口通过 FPGA 转接到电脑，不需要另购 USB 转 TTL 模块，也不增加 MCU。

数据通路为：

```text
触摸屏 TOUCH Type-C
        ↕ USB-A 转 Type-C 数据线
CH9350（SEL=1，下位机模式，负责 USB Host）
        ↕ TX/RX/GND
开发板 J2 扩展口 → FPGA 串口转接测试工程
        ↕ 板上连接，F12/D12
板载 CH340 → 开发板串口 Type-C → 电脑 COM 口
```

这个测试工程原样双向转接串口电平，不产生回显、不解释触摸报告、不自动发送 CH9350 应答。电脑和 CH9350 要设置相同的波特率。正式音画工程的源码、顶层、PLL 和约束不需要改动；板上加载测试工程期间，原有音画功能暂停，之后重新下载原工程即可恢复。

## 1. 在 TD 中打开独立工程

- 工程：`E:/AnLuTD_Project/SD_to_Video/prj/touch_uart_debug/touch_uart_debug.al`
- 顶层：`touch_uart_debug`
- 器件：`EG4S20BG256`
- 源码：`src/touch_uart_debug.v`
- 引脚：`prj/touch_uart_debug/touch_uart_debug.adc`
- 时序：`prj/touch_uart_debug/touch_uart_debug.sdc`

在 TD 中打开上述 `.al`，由你执行综合、布局布线、生成 bitstream，再通过平时使用的下载方式加载到 FPGA。测试顶层只有 4 个串口 IO，无需时钟、复位、PLL 或新 IP。不要把这个顶层替换进现有音画工程。

用 USB 数据线连接电脑与开发板连接 CH340 的 Type-C 串口接口（手册图 2-10 的 USB2）。在设备管理器“端口（COM 和 LPT）”查找板载串口的 COM 编号。你截图中的“符合 HID 标准的触摸屏”是屏幕的 USB HID 设备，不是这里要打开的 COM 口。没有 COM 口时，先检查数据线和 CH340 驱动。

## 2. 先做回环自检

1. CH9350 暂时不接开发板。在测试工程已经加载后，用一根杜邦线短接 **J2 第 1 脚和第 2 脚**。
2. 串口助手打开开发板 CH340 对应的 COM 口，设置 `115200 / 8 数据位 / 无校验 / 1 停止位`，关闭硬件流控。
3. 打开 **HEX 发送和 HEX 接收**，关闭本地回显、自动附加 CR/LF、自动循环发送。
4. 发送 `00 57 AB 82 FF`，接收区应收到完全相同的 5 个字节。
5. 测试成功后，断电并拔掉短接线，再接 CH9350。保留短接线会把串口输出端接在一起，不能用于模块测试。

回环失败时，先核对是否加载了这个测试工程、COM 口是否正确、J2 针脚是否数对。没有通过回环前，不把“没有数据”归因于触摸屏兼容性。

## 3. CH9350 接线

所有针脚均指开发板 **J2 的物理针脚编号**，不是杜邦线颜色或任意 GPIO 序号。按照连接器的 1 脚标识确定方向，J2 的两列分别为奇数和偶数。

| CH9350 模块端子 | 开发板连接 | FPGA 管脚 | 数据方向 |
|---|---|---|---|
| TX | **J2 第 1 脚** | P4 | CH9350 → FPGA → 电脑 |
| RX | **J2 第 2 脚** | N4 | 电脑 → FPGA → CH9350 |
| GND | **J2 第 12 脚** | 地 | 共地 |
| 5V | **J2 第 11 脚**，或独立稳压 5 V | 电源 | 模块供电 |
| 485 控制 | 留空 | — | 本次不用 |

CH9350 模块的 5V 是供电端，不能接到 FPGA 信号脚。芯片手册注明串口输出为 3.3 V；若模块实际另加了电平转换电路，应先确认其 TX 电平。屏幕的 POWER 口按屏幕要求单独供电。J2 的 5 V 为板上电源，当前资料没有给出它可额外带载的保证；若模块 USB VBUS 同时给触摸控制器供电，需要计入这部分电流，电源不足时用独立 5 V 并共地。

用支持数据传输的 USB-A 转 Type-C 线连接 CH9350 的 USB Host 插座与屏幕 **TOUCH** 口。屏幕不能在这一步同时用同一个 TOUCH 口连接电脑。

引脚核对依据：手册第 7 页和当前 `4_GPIO.pdf`、`2_FPGA.pdf`。当前原理图中 J2 第 1、2 脚为连接器 `GPIOB_0/1`，经 RN29 接到内部 `GPIOB20/19`，最终 FPGA 管脚为 P4/N4。板载 CH340 的 F12/D12 同时与手册第 11 页和现有项目 `prj/pin.adc` 一致。

## 4. CH9350 拨码配置

采用默认状态 0 和默认波特率，配置完成后重新上电：

| 功能信号 | 逻辑电平 | 用途 |
|---|---|---|
| SEL | **1（高）** | 下位机模式：CH9350 作为 USB Host 连接屏幕 |
| S0、S1 | **均为 1（高）** | 默认工作状态；单模块使用状态 0 |
| BAUD0、BAUD1 | **均为 1（高）** | 115200 baud |

商品照片中从 1 到 5 的标号对应 SEL、BA1、BA0、S1、S0。以实物背面的标识和 0/1 标记为准；“ON”不一定表示逻辑 1，不要仅根据 ON 字样推断电平。

串口助手继续使用 `115200，8N1，无流控，HEX 接收`。加载 FPGA 测试工程、打开 COM 口后，给 CH9350 重新上电，捕获最开始的数据。

## 5. 观察和保存数据

先观察是否有以 `57 AB` 开头的协议帧。默认状态 0 下，模块可能周期性输出 `57 AB 82 A?` 状态请求；最后一个字节的低 4 位会变化。只收到状态请求，说明串口通路有数据，还不能说明屏幕已被成功识别。

如果捕获到状态 0 的 `82` 请求，可以在 **HEX 发送** 模式手动发送芯片手册给出的 11 字节状态 0 应答：

```text
57 AB 12 00 00 00 00 FF 80 00 20
```

发送的是这些十六进制字节，不是字符串字符；不要追加换行。该应答不构成多点触摸支持的证明。测试工程不自动发送它，便于保留上电时的原始输出。

清空接收区后，分开记录以下几段数据，并注明每段对应的动作：

1. 不触摸，等待约 2 秒。
2. 一根手指按下、停留、横向滑动、松开。
3. 两根手指同时按下，然后只移动第一根。
4. 保持第一根按住，只移动第二根。
5. 松开第一根，第二根继续保持，然后全部松开。

保存原始 HEX 文本或串口助手日志，尽量保留时间戳。不要只发接收字节数。状态 0 的原始 HID 数据通常使用 `57 AB 88 ...` 帧，具体触摸字段需要根据实际输出与 HID 报告格式判断；不同工作状态的帧格式也可能不同。

判断音游能否采用 CH9350，要看这份日志能否保留至少两根手指的独立坐标和按下/松开状态。触摸时有数据、电脑显示屏幕支持多点、或模块输出绝对鼠标坐标，都不能单独证明这条转接链路保留了多点信息。

回环通过但 CH9350 没数据时，先检查模块 5 V、共地、TX/RX、SEL 和波特率，再用普通 USB 键盘或鼠标替换屏幕做对照。若键鼠正常而屏幕无触摸报告，继续查芯片版本和触摸屏 HID 兼容性。

## 6. 已完成的验证

2026-09-30，本地 ModelSim 仿真通过：双向同时连续传输全部 256 种字节，另在 3 Mbaud 下验证 GPIO 回环的 `00 57 AB 82 FF`，无编译或仿真错误、告警。

TD 6.2 综合和布局布线检查通过，最终 IO 报告确认 F12/D12/P4/N4 及 LVCMOS33；占用 4 个 IO、0 LUT、0 寄存器、0 BRAM、0 PLL。两条异步输入到输出路径施加 100 ns 最大延迟约束，报告 STA 覆盖率 100%，WNS 89.551 ns、TNS 0 ns。没有内部时钟，Fmax 不适用于这个工程。

日志在 `prj/log/touch_uart_debug/`。复查命令从仓库根目录运行：

```powershell
& 'E:/AnLuTD/bin/td_commands_prompt.exe' prj/scripts/check_touch_uart_debug.tcl
```

脚本仅检查到布局布线，不执行 bitgen。尚未进行实际板上回环或触摸屏测试，因此 CH9350 对这块屏幕的兼容性、两点数据及实际延迟仍需要上述抓包确认。
