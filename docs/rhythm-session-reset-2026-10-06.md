# 音游资源名称与会话重开显示修复

## 实板反馈与诊断

用户使用 2026-10-05 18:45 的最新 bitstream，普通 BMP 和 WAV 正常，进入游戏显示 ERROR / E7；KEY2 重试仍报错，KEY2 或 KEY4 操作后 UI 在不同位置短暂闪现。

用户确认卡根目录资源已改名为 `Brave_Shine.bin` / `Brave_Shine.WAV`。游戏读取器精确查找 FAT32 根目录短名称 `GAME.BIN` / `GAME.WAV`。E7 表示 WAV 未找到，必须成对恢复转换器的固定输出名称；文件已经拷入卡并不等于匹配游戏名称。普通模式选择普通 WAV，不能作为游戏名称匹配成功的依据。标题来自 BIN 头部，恢复文件名不会改变标题。另保留一个普通 WAV 用于媒体模式，普通模式会排除 GAME.WAV。

UI 错位存在独立的 RTL 原因：会话清理复位渲染器，但没有复位板级扫描。在低有效 VS 的活动区高电平期间，`vs_d` 被复位为零，释放后的高电平制造假 `frame_start`，坐标重新从零开始，直到下一真实 VS 边界才恢复。旧源码的定向诊断复现：

- 第 100 行清理后，实际 `(341,100)` 被渲染器当作 `(5,0)`；实际第 120 行对应内部第 20 行。
- 第 280 行清理后，实际 `(341,280)` 被渲染器当作 `(5,0)`；实际第 300 行对应内部第 20 行。
- 真实 VS 边界之后重新对齐。

诊断输出：`prj/log/rhythm_board_diagnosis_20261006/midframe_reset.log`。已有播放测试在会话清理时也复位模拟 VS 计时，显示测试仅在帧间复位，未覆盖这个实板边界。

## 修复范围

`rhythm_game_renderer.v` 增加 `vs_seen_low`，复位后只有观察到 VS 低电平，才能接受随后真实上升沿。游戏图层在重新同步前保持关闭，HUD 和几何快照共同使用经过确认的帧边界。真实边界后在消隐期完成重建，随后显示完整对齐的一帧。清理跨越 VS 上升沿而释放时 VS 已高的情况，会继续等待下一同步周期。

保留现有像素流水、几何算法、字体/字符 RAM 和低有效 640×480 时序。顶层、接口、管脚、时钟、PLL、工程和厂商 IP 未修改。资源读取器仍按既定固定名称查找；本次没有增加长文件名解析或多曲选择。
