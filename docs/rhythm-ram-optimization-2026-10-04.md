# 音游队列打包与块 RAM 重分配

## 范围与比赛要求

图片缩放必须采用双线性插值算法。本轮保留任意尺寸双线性缩放、五图预装、2048 点 FFT、Hann 窗、80 柱环形频谱和呼吸效果，针对音游队列与 FFT 数据区调整存储组织。

不改变顶层外部接口、管脚、PLL、时钟和厂商 IP；直接使用器件已有 RAM 原语，不生成新 IP 或 bitstream。触摸屏/键盘尚未接入，偶发彩色/白色横线问题仍未关闭。

## 音游队列

- 仍为四轨、每轨八槽，共 32 条活动音符，时间、偏移、Tap/Hold、计分和事件时间锁存规则保持。
- 原判定和显示镜像各为 `32×64` 位，由宽端口各映射四片 BRAM32K，合计八片。
- 每条 `{结束时间[31:0],开始时间[31:0]}` 拆为四个 16 位字：字 0/1 为开始时间低/高半字，字 2/3 为结束时间低/高半字。
- 两份镜像各为 `128×16` 位，每份映射一片 BRAM9K，合计两片。有效数据总量仍为 512 字节，保留两条独立读通道，避免判定与绘图争用读端口。
- 音符握手拍写入字 0，并锁存记录地址和剩余 48 位；后续三拍写字 1～3，期间 `note_ready=0`。写入不会随游戏暂停或绘图冻结而停在半条记录；复位会取消剩余字并清有效指针。
- 同步读分四个字组装。完成标签和当前装配标签都与请求记录匹配，且没有在途写入时，才允许判定或输出有效视图。写入会使读缓存无效，完成后重新完整读取，隔离 RAM 旧内容和读写碰撞。
- 判定扫描等待所需记录有效，四轨事件仍使用接收时锁存的时间。AUTO 换轨等待八拍，并记录已接收事件的在途状态，直到判定器再次空闲才生成新事件，避免串行访问时重复读取队头。
- 渲染快照首槽等待十二拍，容纳至多三拍在途写入和窄 RAM 取数；后续每次换槽等待八拍。每行几何扫描与像素延迟不变。真实队列与渲染器的快照重叠测试核对全部 32 条几何数据。

## FFT 存储重分配

原两个 `2048×32` FFT 数据区各占八片 BRAM9K。利用队列释放的 BRAM32K，每个数据区显式采用现有 `EG_LOGIC_BRAM` 原语的 BRAM32K 实现，各占两片，合计四片 BRAM32K。

读使能、同步一拍读延迟、禁止读时保持输出以及独立读写地址保持。256/512 点的存储继续采用原推断方式。FFT 运算、旋转因子、幅度、频谱柱、呼吸与帧边界发布逻辑未改。

## 整板综合结果

基线为 `prj/log/rhythm_stage4_release_syn/`，最终报告为 `prj/log/rhythm_ram_final_syn/`。中间候选 `rhythm_ram_candidate_syn` 不作为当前正式报告。

| 资源 | 第四阶段基线 | 本轮最终 | 变化/剩余 |
|---|---:|---:|---:|
| LUT | 19540/19600 | 19566/19600（99.83%） | 增加 26，剩余 34 |
| REG | 12150/19600 | 12365/19600 | 增加 215 |
| BRAM9K | 47 | 33 | 减少 14 |
| FIFO9K | 16 | 16 | 保持 |
| BRAM9K/FIFO9K 合计 | 63/64 | 49/64（76.56%） | 剩余 15 |
| BRAM32K | 15/16 | 11/16（68.75%） | 剩余 5 |
| DSP | 18/29 | 18/29 | 剩余 11 |

队列移出八片 BRAM32K、新增两片 BRAM9K；FFT 移出十六片 BRAM9K、新增四片 BRAM32K。因此整板净减少十四片 BRAM9K和四片 BRAM32K。寄存器与 LUT 增量用于字片缓存、标签、反压和等待控制；本轮目标是释放 RAM，未解决 LUT 余量。

双线性缩放器仍映射四片 BRAM32K、三颗 DSP，源像素 FIFO 两片 BRAM32K，标题缓存一片 BRAM32K，FFT 两区四片 BRAM32K，合计十一片。

综合零错误、66 条告警，与第四阶段基线告警分类及数量一致，涉及已有厂商/加密模块、兼容 FFT 常量、RAM 字节使能/初始化和未驱动引脚等，不新增告警类别。

| 时序指标 | 第四阶段基线 | 本轮最终 |
|---|---:|---:|
| setup WNS | −0.846 ns | −0.291 ns |
| setup TNS | −16.163 ns | −7.017 ns |
| hold WNS / TNS | +0.471 ns / 0 | +0.471 ns / 0 |
| STA coverage | 99.93% | 99.93% |

视频域 setup +7.326 ns / Fmax 30.605 MHz；SD 域 setup −0.291 ns / Fmax 97.172 MHz，仍未满足 100 MHz。SD 首条关键路径从共享扇区仲裁器 `state_reg[1]` 到 BMP 读取器 `top_down_reg`，数据路径 10.175 ns，网络延迟约占 66%。`ext_mem_clk_sft` 仍有 −0.213 ns 裕量。

本轮只综合，没有 P&R；综合估计改善不能代表路由或上板通过。LUT 仅剩 34，仍需下一轮针对 LUT 和控制时序优化，再做最终布局布线。不得通过删除双线性缩放满足资源目标。

## 验证与复现

使用 ModelSim 10.3c 和 TD 6.2。以下 Python 命令在项目根目录执行；日志均保存在 `prj/log/`，不生成 bitstream。

```powershell
python src/test/run_rhythm_stage3.py --output prj/log/rhythm_ram_final_stage3
python src/test/run_rhythm_stage4.py --output prj/log/rhythm_ram_final_stage4
python src/test/run_resource_regression.py --output prj/log/rhythm_ram_media_fft
python src/test/run_resource_build.py rhythm_ram_final_syn --rhythm
```

上述回归全部通过：队列/判定六项和游戏会话/显示五项，均零错误、零告警；频谱/媒体/缩放二十六项，零错误，真实厂商 FIFO 集成的两个变体各保留原有十二条可选端口告警，其余无告警。

- 队列与判定：分布式/窄 RAM 两种判定边界、Hold、暂停、四轨和弦锁存时间、偏移、八槽满队列、复位；32 条全位宽记录、写入反压、地址快速跳转、写入中断复位、写入与显示快照重叠；65535 条音符及环形指针绕回、精确百万分；真实 413 音符 AUTO 满分和 TEST 全 Miss。
- 第四阶段：会话控制、显示像素/HUD/几何与进度、10000 帧 PCM 播放闭环、暂停/欠载/恢复/重开/EOF/结果/退出、媒体控制冻结与图片提交保护。
- FFT 与媒体：真实 BRAM32K 模型的全部 2048 地址、同步一拍、双端口及读使能保持；优化前后逐块频谱/呼吸/帧发布/复位对照；2048 点频率与幅度；旧媒体 FAT32/碎片读取、五图目录、双线性缩放边界/640×480 和真实源像素 FIFO 提交。
- 新窄存储回归没有通过降低音符容量、截断时间位宽、减少 FFT 点数或扩大判定窗规避问题。65535 条串行访问测试实测约 199.23 ms 仿真时间，超时预算从 100 ms 调整为 400 ms，断言保持。
- 旧版 OEM 编译器在直接打印某些层次变量时发生内部错误；测试改用等价的本地观测线，设计行为及检查条件保持。

原工程、PLL 和 debug 工程未提交修改，以及 `docs/history/` 均保留。
