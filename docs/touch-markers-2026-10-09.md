## 映射参数

横放、640×480、画面铺满屏幕，不交换轴也不翻转。采用用户最后确认的范围：

| 项目 | 原始十六进制 | 十进制 |
|---|---|---:|
| X 最小 | 0060 | 96 |
| X 最大 | 3F10 | 16144 |
| Y 最小 | 0080 | 128 |
| Y 最大 | 24E0 | 9440 |

先对原始坐标钳位，随后减最小值，防止无符号下溢。映射为：

```text
dx = clamp(raw_x, 96, 16144) - 96
dy = clamp(raw_y, 128, 9440) - 128
pixel_x = clamp((dx * 2610 + 32768) >> 16, 0, 639)
pixel_y = clamp((dy * 3371 + 32768) >> 16, 0, 479)
```

两个端点精确映射到 0/639 和 0/479，定点结果相对精确比例取整误差不超过一个像素。旧中心采样 1FA0/12D0 映射到 (319,241)，最新中心 1ED0/11B0 到 (310,226)。不根据第二次中心采样移动整体范围，先上屏核对。

参数在 `touch_pixel_mapper` 的 X_MIN/X_MAX/Y_MIN/Y_MAX 和 X_SCALE_Q16/Y_SCALE_Q16 中；改变边界时要同时重算系数并重跑回归。机器可读记录见 `touch-calibration-2026-10-09.json`。

## 电路和时序

- `touch_pixel_mapper.v` 在现有 50 MHz 域用一个共享 EG_LOGIC_MULT DSP，依次计算 A.X/A.Y/B.X/B.Y；12 个时钟完成整份映射。默认 ATOMIC_OUTPUT=1 原子发布40位包；主工程为节省重复存储设0，只有pixel_valid后才使用计算结果。期间出现新输入更新，则重启并以最新报告为准。解析器坐标保持到下一次更新，当前串口报告间隔远大于计算时间。
- 包布局：A按住/B按住/A.X10位/A.Y9位/B.X10位/B.Y9位。坐标不带硬件编号，因为标记只使用已按编号维护好的 A/B 槽。
- `touch_frame_snapshot.v` 在VS上升沿通过两级同步toggle向源域发出sample_request，映射器随后计算最新完整包，pixel_valid确认完成后才返回应答。源结果保持到下一次请求，接收端消隐期锁存并整帧保持。只有请求或计算中新的触摸报告才启动映射，避免在应答传递期间改写源数据；无需额外40位源信箱、逐位同步坐标总线或新增时钟/PLL。
- 当前视频帧开始之后到首个有效像素有充分消隐时间；不能把该快照模块用于没有消隐时间的任意 frame_start。两个复位由同一个板级复位断言。
- `touch_marker.v` 在 `video_presentation` 的第一级计算十字命中，第二级覆盖 RGB，与原图、DE/VS 保持同样两拍延迟。独立的触点行计数在 DE 下降沿递增，避免首行/末行偏移；原有频谱/图像坐标逻辑保留。
- `video_presentation.ENABLE_TOUCH_MARKERS` 默认 0，主工程显式设 1。原有默认显示模式不产生新标记。

主工程仍采用用户已批准的 `VIDEO_SIGNATURE_DIAGNOSTICS=0` 配置，保留刷新、FIFO 空读、反压诊断；D/F/C 签名页保持关闭。

为给新显示逻辑腾出 MSlice，串口快照队列改用现有器件 BRAM9K 原语，同步读取有准备标志，同地址写时暂停读以避免跨端口碰撞。五个槽包含正在发送的一项，等效于原来的四项等待队列加在发送快照；当前快照在整条 T 行发送完成后才出队，全部触点字段来自同一报告。

文本格式化逐字段锁存16位数值，省去整行144位暂存。统计行用小型状态机输出字段名与数字，避免对整条83字符行建立大范围组合选择逻辑。S行中每个计数都是完整16位原子取样，但九个计数不再强制在同一时刻取样，它们的取样时刻相差几毫秒；T行仍为完整、同一时刻的双点快照。T/S字段、事件优先级、回显顺序和溢出计数保持。普通坐标限频、UART位周期和半帧超时计数器按实际参数缩小位宽，时间间隔和波特率不变。

四个统计计数的递增加法也改用DSP组合乘法等价实现：`(65536+n)*65537` 的第31:16位恰好是 `(n+1) mod 65536`。没有寄存器延迟或更新仲裁，四个计数仍可同时更新；全部65536种输入已核对。这里使用四个DSP，坐标映射使用另一个DSP。没有生成或修改厂商 IP。
