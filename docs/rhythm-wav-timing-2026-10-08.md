# 曲尾 BUFFERING 的 WAV 播放推进时序修复（2026-10-08）

## 结论与范围

用户使用最新 bit 流，Brave Shine 每次接近曲尾、剩约 2～3 秒时显示 BUFFERING，音乐和音块一起暂停后恢复。直接机制是播放器欠载，歌曲时间与判定冻结，缓冲恢复后继续。90.071 秒曲目约 87.381 秒经过 WAV 的 16 MiB 文件位置边界，与反馈位置吻合，但尚未捕获实板读地址/数据/水位，不能唯一认定根因。

用户要求先修复时序，若实板仍卡顿再做边界定向仿真。本轮没有新增 16 MiB 定向仿真，仅进行修改必需的接口与播放回归。

保留并提交的是已完成默认布局布线、实测文件位置/EOF/扇区字节计数路径全部正裕量的首轮候选。随后尝试改善剩余启动路径的两个候选分别导致严重时序恶化和布线失败，已撤回。**本轮消除了 WAV 播放推进相关的已知违例，整板尚未全部时序闭合。**

## 保留修改

- `fat32_wav_reader.v` 将完整文件位置比较锁存为 `file_complete`。数据扇区退场增加一个等待拍，再使用锁存结果选择 EOF、下一扇区或 FAT 查询。最后字节与 done 同拍也提交完整计数及 PCM；取消仍等待已接受扇区结束。
- 逐字节接收使用十位 `data_bytes_left`，每次请求前根据对齐文件位置加载 512 或末扇区有效字节数。减少 32 位比较对字节接收/PCM/计数寄存器的控制扇出；保持完整 32 位文件长度，不消费末扇区填充字节。
- 目录长度三字节暂存独立于高扇出 FSM 译码。其它事务写入的临时值无效，完整描述符仍只在 DIR 状态的目录项末字节发布；文件长度、精确 GAME 名称及目录查找不变。
- 扩展规范 WAV 测试的连续字节模式，核对背靠背字节、部分/完整末扇区、格式错误、碎片、媒体循环及游戏 EOF。补充目录扫描上限检查，保留原 1024 扇区边界。

## 未保留的尝试

- 错误原因编码与目录计数另拍消费的候选：综合 SD setup +0.024 ns，但实际 P&R 全域 -8.746/-1544.443 ns、hold -0.052/-0.169 ns，最差缩放器路径的连线占延迟85%，视频路径也恶化。记录在 `rhythm_wav_timing_final_syn_20261008/`、`rhythm_wav_timing_final_phy_20261008/`。
- 将该候选目录计数缩到11位：综合 LUT17756/REG10525、SD setup +0.037 ns，实际默认 route 报 RUN-8102/PHY-8023，争用视频监视器及谱面网络。记录在 `rhythm_wav_timing_release_syn_20261008/`、`rhythm_wav_timing_release_phy_20261008/`。未交付。

这些尝试说明当前高占用设计对布局敏感，不能以综合正裕量替代实际布线检查。当前源码已恢复到首轮通过布线的逻辑，最终回归重新核对。
