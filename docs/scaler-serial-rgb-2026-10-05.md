## 资源与时序验收

实施前控制综合 `prj/log/scaler_serial_control_syn/` 与候选 `prj/log/scaler_serial_candidate_syn/` 使用相同当前工程、源集、TD 默认综合参数和时钟约束。本轮只有这两次综合，没有中间优化综合、物理实现或 bitstream。

口径：LUT 为普通 LUT 加 ripple；父模块含子模块，不重复累计。整板 REG 采用 utilization 统计，模块 SEQ 采用层次统计，二者因 IO 寄存器统计范围存在差异。

## 实现与实际映射

- 缩放器新增默认关闭的 `SERIAL_RGB`；SD 管线通过默认关闭的 `SCALER_SERIAL_RGB` 传递，板级开启。原三 DSP 模式保留，外部端口不变。
- 四个源像素、权重和坐标在整像素处理期间保持。R/G/B 依次完成六个乘积阶段和一次舍入；共享第一个显式 DSP、一条 24 位加法通路、一组水平 16 位中间结果和垂直累加器。
- R/G/B 分别舍入后暂存于 24 位结果寄存器，完成三个通道后才发布完整像素。最终舍入仍加 32768 后取高八位；双线性结果及坐标端点规则保持。
- 反压时 RGB、坐标及行/帧尾稳定。复位或 abort 清输出有效和通道计数，重新启动从 R 开始。源 FIFO 深度及扇区水位门槛保持；等待发生在扇区之间。
- 导出网表 `mapped_check.v` 和 `mapped_counts.json` 确认缩放器只有一个 `EG_PHY_MULT18`，535 个 `AL_MAP_SEQ`，没有剩余 G/B 累加、水平/垂直结果或第二、第三乘法器输入寄存器。共享 `sum_r` 对应一条 `add14` 进位链。原行缓存仍为四个层次 BRAM，未改厂商 IP。

## 本轮发现的五图首显边界问题

原首显条件以 `catalog_done && !candidate_valid && !load_inflight` 判断预装结束。但目录 BRAM 在两个描述符之间需要多拍读取，`candidate_valid` 的空档会被误判为没有剩余候选。

新增五图连续扇区测试在原三 DSP 模式下复现：目录已找到五个候选，实际仅写完第一图的 3,072 个目标像素就开始显示，而预期为 15,360。此前“当前工程必定五图预装完成才首显”的描述不覆盖这个空档问题。

为落实批准方案，候选在管线内部新增三位已释放候选计数：成功提交和加载失败释放都计数，只有目录结束且释放数量达到候选总数才向会话控制器提供完成条件。避免损坏 BMP 导致永久等待，不改目录器接口或 RTL。五个有效文件及首、中、末损坏文件场景均通过。

**这项修复与串行候选一起保存，主分支恢复基线后也未采用修复，当前工程仍存在该已复现的首显边界问题。** 后续可将其作为单独修复候选验收，不能声称本轮已经修复主工程。

## 功能回归与等待测量

主回归 `prj/log/scaler_serial_regression/` 共 16 项仿真全部通过：

- 串行数学参考和默认兼容数学参考各一项；独立旧 RTL 尺寸/生命周期对照一项、640×480 整帧对照一项。覆盖 1×1、单行、单列、1920×1080 最大源尺寸、随机像素与极值、输入空拍、连续长反压、RGB 各通道中途 abort/复位及不复位重启、非法尺寸。
- 真实源 FIFO 五图预装两模式、首/中/末坏文件共五项；默认/串行提交、串行共享会话取消三项；音频低水位优先、两种返回寄存模式及媒体会话四项。

另有 `prj/log/scaler_serial_rhythm_regression/` 五项既有回归通过：游戏会话、显示、携带帧号的真实 PCM 播放闭环、媒体冻结、图片显示保护。合计 21 项，无测试失败。

最终测试编译全部零错误、零告警；纯缩放对照零错误/零告警。真实 FIFO 集成每项保留厂商包装的十二条既有可选端口告警，既有仲裁测试四条、游戏播放测试三条未连接端口告警；未修改这些厂商或既有测试接口。本轮控制与候选综合均零错误/68 条告警，各类别及数量完全相同，无新增综合告警。

| 测量条件（100 MHz） | 原三 DSP | 单 DSP | 增量 |
|---|---:|---:|---:|
| 单图 640×480，无输入空拍/输出反压 | 3,688,379 拍 | 8,296,379 拍 | 4,608,000 拍＝46.08 ms |

五图串行夹具 FIFO 最高占用 483/512，水位阻塞 255,725 拍，无溢出。首显只在所有有效图片完整提交后发生；坏文件候选被释放，四个有效槽仍可完整预装和显示。

## 复现和交付

候选测试脚本只存在于候选分支。先保留工作目录已有修改，切换分支后使用 PATH 中的 ModelSim `vlib/vlog/vsim` 和 Python：

```powershell
git switch codex/scaler-serial-rgb-candidate
python src/test/run_scaler_serial_regression.py --baseline-ref 436b44e --output prj/log/scaler_serial_recheck
python src/test/run_rhythm_stage4.py --output prj/log/scaler_serial_rhythm_recheck
python src/test/run_resource_build.py scaler_serial_recheck_syn --rhythm
```

当前 main 的 RTL 已恢复实施前版本，候选八个源码/测试文件提交在 `ee96406`；主分支仅更新本记录、JSON 快照及 current-state。用户四个工程/PLL/debug 修改文件 SHA256 保留，历史目录保留，未纳入提交。外部端口、管脚、时钟、约束、PLL 与厂商 IP 均未改。

本轮没有物理实现或 bitstream。最近实际打包仍是前轮 5,300 MSlice，超过 4,900；本轮资源降幅不能证明容量达标。下一步若继续此方向，应针对 SD 关键路径做独立时序修复，再联合验收候选；不能通过降低时钟约束将启动等待与时序违例混为一谈。
